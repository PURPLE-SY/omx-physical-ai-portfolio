# 데이터 품질 분석과 오류 해결 이력

원본 데이터는 수정하지 않고 분석했으며, 보정은 별도 사본으로만 만들었다. 각 항목의 숫자는 괄호 안 근거 파일에서 인용했다. 근거 파일은 모두 로컬 작업 PC에 있고, 이 저장소에는 포함하지 않았다.

## 1. 11/14 녹화 시간축 불일치 (metadata 30 Hz ↔ 실제 약 13~15 Hz)
근거: `omx_logs/time-axis-20261116/REPORT.md`

- **대상:** `pick_place_11_14_S01_F03_` ~ `S06_F03`, 158 에피소드(S01~S05 각 30, S06 8)
- **실제 루프:** 11.7~19.0 Hz, 세션 중앙값 13.3~15.3 Hz
- **기록 방식:** 행마다 `timestamp = 행번호/30`으로 저장되고, 영상 PTS도 1/30으로 고정됨
- **결과:** 저장된 길이가 실제의 1/1.58~1/2.56로 압축됨(예: S04 E27 실제 38.26 s → 저장 16.0 s)
  - 영상뿐 아니라 `observation.state`·`action` 시간축도 같은 비율로 압축됨
- **정상인 부분:** 행 내부 대응. 158개 모두 action = 실제 전송 목표, 행 수 = 영상 프레임 수
- **원본 보존:** 원본 해시 144개를 재확인했고 변경 0
- **세션 내 감속:** S01~S04가 뒤로 갈수록 느려진 원인은 **미확인**

## 3. 0.5초 정지가 1프레임으로 압축되는 문제
근거: `_validation_20261123/REPORT.md:30-31`, `_validation_20261124/REPORT.md:89`

- **왼팔:** 작업당 0.5초 멈춤이 24~35회(약 15~30초에 1회) 있었음
  - 멈춘 0.5초가 데이터에서는 1프레임으로 압축됨 → 시간 왜곡 약 3~5%
- **오른팔:** 0.5초 멈춤 0회
- **0.4초 넘는 루프 정지:**
  - L 11-22 EX에서 14개(0.53~0.58 s)
  - R_11_21_F02_S05 ep2에서 1.24 s
- **조치:** 팔로워 Return_Delay_Time을 50으로 바꿔 sync-read 0.5초 멈춤을 약 1/6로 줄임(앱 저장소 커밋). 움직일 때는 약 16초에 1번 남음
- **미확인:** 근본 원인(하드웨어/통신)
