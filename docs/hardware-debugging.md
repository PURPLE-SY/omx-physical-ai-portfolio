# 하드웨어 디버깅 기록

사실(로그·레지스터 읽기로 확인한 것)과 추정을 나눠 적었다. 원인을 확정하지 못한 항목은 "미확정"으로 표시했다.

| 문제 | 확인한 사실 | 조치 | 상태 |
|---|---|---|---|
| 오른팔 shoulder_lift(ID12) 추종 이상·처짐 | 11-21·11-24 추적 기록에서 처짐. 부하 1000(100%) 도달 후 종료 시 Torque_Enable 쓰기 거부(Hardware error). P640일 때 리더보다 최대 약 9° 처짐 | 오른팔 shoulder_lift만 P1500으로 올림. 추가 녹화 중단 | 원인 미확정 (고부하 가설) |
| B팔 elbow(ID13) 과부하 | 11-26 21:27, 11-27 00:33에 hw 0x20(overload). 종료 중 토크를 끄지 못해 ID14~16 토크 잔류. 실행별 최대 부하 230→331→449→463→511 | 사용자 승인 후 ID14~16 토크 수동 OFF. 전원 재시작으로 해제 | 원인 미해결 |
| 팔로워 PWM 한도 20 / XL330 전류 한도 50 | 11-25, 11-26 USB 재연결 이후 두 번 관측. 한도가 낮으면 팔이 거의 움직이지 않음 | 경위 확인 전 자동 복원을 금지함. 사전 점검에서 막도록 함. 담당자(사용자) 승인 후 885/500으로 복원 | 낮아진 원인 미확인 |
| 정책 실행 경로의 게인 누락 | 정책 실행 시 shoulder_lift가 LeRobot 하드코딩 P4000/D600으로 동작(고정값 P640/D3600 아님) | 실행 경로에 고정 게인 적용과 다시 읽어 확인하는 단계 추가(단위 테스트 6개). 로그에 `>> follower gains fixed` 확인 | 해결 (실물 로그 확인) |
| sync-read 0.5초 멈춤 | 왼팔 작업당 24~35회, 데이터에서 1프레임으로 압축됨 | Return_Delay_Time 50으로 약 1/6 감소 | 움직일 때 잔존 |
| 팔로워 USB 분리 | 11-26 23:35 통신 시험 중 커널 "USB disconnect" | 재연결 후 sync_read 900회 중 실패 0 확인 | 재발 여부 관찰 중 |
| 카메라 | Jieli 검은 화면(평균 밝기 0), RealSense USB 2.1 인식, RealSense by-id 시리얼과 모듈 시리얼이 달라 오탐 | `usbreset`, 재연결. 사전 점검을 pyrealsense 조회로 수정 | 해결. 검은 화면은 사전 점검이 잡지 못함(개선 필요) |
| 리더 전압 3.8~4.1 V | 리더 ID4~6 입력 전압 오류 | 5 V 전원 확인 필요로 기록 | 미해결 |
| 실행 창 강제 종료 | 정책 프로세스가 종료 처리 없이 끝나 토크 잔류 | 종료는 q로 하도록 운영 규칙화 | 운영 규칙 |
| 손목 엔코더 경계 | 리더 wrist_roll 경계가 시작 자세 근처라 재연결할 때 회전 수가 바뀜 | 녹화 전 손목 기준 관문(boot_id·장치 기준 파일) | 근본 해결은 손목 혼 재조립 필요 |
